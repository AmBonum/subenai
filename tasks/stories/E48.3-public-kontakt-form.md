## Context

The public-facing support entry point. Slovak copy, mobile-first,
discoverable from the footer + the existing `/podpora` page. Single page,
no router-level form library — `react-hook-form` + `zod` resolver as
elsewhere in the app.

PLAN §"UI — surface inventory" + §"Decisions D-2, D-4, D-9, D-10" specify
the spam-defence and CSP details.

## Acceptance criteria

- **AC-1:** Route `/kontakt` ships at `src/routes/kontakt/index.tsx`. Robots: `index, follow`. `<title>`: "Kontakt | subenai" or copy-team-approved equivalent. `meta description`: 140–160 chars. Structured data: `ContactPage` JSON-LD with `email` from `support_config`.
- **AC-2:** Form fields:
  - Subject (`text`, required, 1–200 chars)
  - Category (`select`, required) — 7 options from `support_ticket_category` enum, Slovak labels
  - Body (`textarea`, required, 1–5000 chars, live counter)
  - Email (`email`, required, regex validated)
  - Name (`text`, optional, ≤ 100 chars)
  - Attachments (dropzone, JPG/PNG/PDF, max 5 × 5 MB; uploaded via `/functions/api/support-attachment-upload.ts`)
  - Honeypot (`text`, name `_h_addr`, `aria-hidden`, off-screen positioned via CSS `position: absolute; left: -9999px`, `tabindex="-1"`, `autocomplete="off"`)
  - Cloudflare Turnstile widget (managed mode — invisible to most users)
- **AC-3:** Submit calls `/functions/api/support-ticket-create.ts` (new). The function:
  - Verifies Turnstile token via the Cloudflare verify endpoint
  - Verifies honeypot empty
  - Checks per-IP rate limit (3 per 24h, via CF KV — namespace `SUPPORT_RATE_LIMIT`)
  - Calls `submit_support_ticket()` RPC
  - Returns `{ ticket_id, view_token }`
  - Triggers confirmation email (E48.5)
- **AC-4:** Success state — redirect to `/kontakt/odoslane?id=<ticket_id>` showing the ticket id, view-link explanation, expected response time, link to `/kontakt/ticket/$id?token=$token` (anonymous-friendly read view). Robots: `noindex`.
- **AC-5:** Read view at `/kontakt/ticket/$id?token=$token` — server-validates the token via HMAC comparison; renders the thread (subject, status badge, message list with sender names + timestamps); shows attachments as scan-status badges (only "clean" shows download link); no reply box (inbound parsing out of scope). Robots: `noindex`.
- **AC-6:** CSP updated in `public/_headers`: add `https://challenges.cloudflare.com` to `script-src` and `frame-src`. No other relaxation.
- **AC-7:** All interactive elements have `data-testid` per CLAUDE.md naming: `kontakt-form-subject-input`, `kontakt-form-category-select`, `kontakt-form-body-textarea`, `kontakt-form-email-input`, `kontakt-form-name-input`, `kontakt-form-dropzone`, `kontakt-form-submit-button`, `kontakt-form-error-{field}`, `kontakt-form-honeypot` (hidden but present for tests).
- **AC-8:** Accessibility: form labels programmatically associated; live region for upload progress + scan status; error messages associated via `aria-describedby`; submit button shows loading state with `aria-busy`. Tested with axe-core in Playwright spec.
- **AC-9:** SEO meta: structured data renders; OG tags (`og:title`, `og:description`, `og:image` from the existing OG generator); canonical URL.
- **AC-10:** Footer gets a new "Kontakt" link (single-row commit in the existing `Footer.tsx`).
