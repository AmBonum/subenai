## Context

Detail testu mal tri záložky (Výsledky / Analytika / Nastavenia) a žiadny
spôsob, ako po publikovaní zmeniť otázky. Tento story uzatvára najťažší
UX gap epicu: po-publish editovateľnosť.

## Akceptačné kritériá

- **AC-1:** `/app/tests/$testId` má novú záložku **Otázky** s test-id
  `test-editor-tabs-questions`. URL zachováva `?tab=questions`.
- **AC-2:** Záložka Otázky renderuje komponentu
  `<QuestionsEditor testId questionIds />` (test-id `test-editor-questions-root`),
  ktorá:
  - ak `questionIds.length === 0` zobrazuje empty-state (`test-editor-questions-empty-state`)
    s CTA tlačidlom (`test-editor-questions-empty-cta`);
  - inak vykresľuje zoradený zoznam s testid `test-editor-questions-list`,
    pričom každý riadok má `position`, `prompt`, badges, `up`, `down`,
    `remove` tlačidlá v pomenovanom `test-editor-questions-row-<id>-*` namespace.
- **AC-3:** „Pridať otázky" otvára existujúci `QuestionPickerDialog` (PR #79)
  s `excludeIds` rovnými aktuálnemu poradiu — picker neukáže duplicitné
  otázky.
- **AC-4:** Reorder (`up` / `down`) je **optimistický** — lokálne UI sa
  prehodí okamžite, kým je `useUpdateTestQuestionOrder` v lete; pri chybe sa
  resyncujeme zo servera.
- **AC-5:** Pri pokuse o odstránenie otázky, na ktorú už respondent odpovedal,
  surface-ujeme hlášku `editor.questions.remove_blocked_fk` (R1 mitigation):
  *„Túto otázku nie je možné odstrániť — niektorí respondenti už na ňu
  odpovedali."*
- **AC-6:** Nastavenia tab obsahuje `<OrderModeToggle testId value />`
  (test-id `test-editor-order-mode-root`) s dvomi `RadioGroupItem`-mi
  (`test-editor-order-mode-radio-fixed` / `-random`). Zmena vyvolá
  `useUpdateTestOrderMode` a re-fetch detailu.
- **AC-7:** Všetky 3 jazykové súbory (`sk/en/cs tests.json`) majú nové
  i18n kľúče v `editor.questions.*` a `editor.order_mode.*`.
