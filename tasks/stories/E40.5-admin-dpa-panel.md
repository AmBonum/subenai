# E40.5 — `/admin/dpa-requests` list + detail + status flips

**Epic:** [E40 — DPA automation](../PLAN-2026-05-20-E40-dpa-automation.md)
**Effort:** `M` (≤ 2 days)
**Priority:** `P2`
**Status:** 🟡 Ready

## Context

Operator-side workflow. Admin opens `/admin/dpa-requests`, sees who has asked for a DPA, when, for which school, and whether the e-mail copy actually delivered. From the detail view admin can:
- Flip status (`pending` → `delivered` → `signed`).
- Re-send the e-mail copy if the original `email_status='failed'`.
- Trigger anonymisation early (manual override of the 12-month auto-cron — when the school explicitly asks for deletion under Art. 17 GDPR).
- Download the original PDF that was generated (regenerated on demand from `dpa_version` + the row's data — we don't store the binary).

Reuses the layout patterns from `/admin/dsr` ([AH-7.5-admin-dsr-queue.md](./AH-7.5-admin-dsr-queue.md)) and `/admin/respondents` ([AH-7.3-admin-respondents-list.md](./AH-7.3-admin-respondents-list.md)).

## Acceptance criteria

- **AC-1**: New route file `src/routes/admin/dpa-requests.tsx`:
  - Admin-only (role + `aal2` gated — same as the rest of `/admin/*`).
  - List view: table with columns `created_at`, `school_name`, `contact_name`, `contact_email`, `dpa_version`, `status` (badge), `email_status` (badge), action column with "Detail" + "Re-send e-mail" buttons.
  - Search input (filter by `school_name` via the trigram index).
  - Date range filter (`created_at` from/to).
  - Status filter (multi-select chips: pending / delivered / signed / cancelled).
  - Pagination — page size 25.
- **AC-2**: Detail drawer / dialog (open on row click):
  - All row fields read-only displayed.
  - Status dropdown (admin can change → writes via Supabase update + audit-log entry).
  - "Re-send e-mail" button → calls server fn `resendDpaEmail({ requestId })`; the server fn re-renders the PDF with the SAME `dpa_version` the original used, calls `sendDpaEmail`, updates `email_status`.
  - "Download PDF" button → same render path as re-send, returns blob to browser.
  - "Anonymise now" button (destructive, confirm dialog) → calls server fn `anonymizeDpaRequest({ requestId })` which writes NULL on `contact_name` + `contact_email`, sets `anonymized_at=now()`. Logs to `audit_log`.
- **AC-3**: Audit-log integration — every status flip, every re-send, every manual anonymisation writes an entry to `audit_log` with `action`, `actor_id`, `target_table='dpa_requests'`, `target_id`, `meta` (the diff).
- **AC-4**: Admin navigation — new nav entry in [src/routes/admin/_shell.tsx](../../src/routes/admin/_shell.tsx) (or wherever the admin sidebar lives): "Žiadosti o DPA" under the GDPR section, between "DSR" and "Audit log". Icon: `<FileSignature />` (lucide-react, already imported by `SchoolsGdprCard`).
- **AC-5**: Test-ids: every interactive element on the admin page gets a `admin-dpa-requests-*` test-id. Drawer / dialog has its own `admin-dpa-requests-detail-*` prefix.
