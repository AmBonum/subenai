# E48.5 — Confirmation e-mails (Slovak templates) wired into Resend

**Epic:** E48 — Support contact form + admin ticketing system
**Effort:** `S` (~½ day)
**Priority:** `P0`
**Status:** 🟡 Ready
**Branch:** `feature/E48-support-ticketing`
**Commit prefix:** `feat(email):`
**Dependencies:** E48.1 (ticket rows), E48.3 (CF submission function)

## Context

Three Slovak transactional templates clone the existing
`dpaDeliveryEmail` pattern in `/functions/_lib/email-templates.ts` (HTML
+ plain-text fallback + canonical company footer). Triggered from
existing CF functions; no new dispatcher needed.

## Acceptance criteria

- **AC-1:** Template `supportTicketReceivedEmail({ ticketId, viewToken, viewUrl, subject, category })` in `/functions/_lib/email-templates.ts`:
  - Subject: "Vašu žiadosť o podporu sme prijali — {ticketId}"
  - Body: greeting, summary of the submission ("Téma: {subject}, kategória: {category}"), expected response time ("odpovieme do 2 pracovných dní"), view link (`viewUrl`) for anonymous submitters only, footer.
- **AC-2:** Template `supportTicketReplyEmail({ ticketId, replyBody, adminName, viewUrl })`:
  - Subject: "Re: vaša žiadosť o podporu — {ticketId}"
  - Body: admin reply text rendered with line-breaks preserved (`<br>` escaping; no Markdown rendered), admin display name, "Odpovedať možno kliknutím na 'Odpovedať' v tomto e-maile" instruction, view link, footer.
- **AC-3:** Template `supportTicketResolvedEmail({ ticketId, viewUrl })`:
  - Subject: "Vaša žiadosť o podporu bola uzavretá — {ticketId}"
  - Body: notification of resolution, view link to thread, "Ak potrebujete znovu otvoriť, odpovedzte na tento e-mail" instruction, footer.
- **AC-4:** `/functions/api/support-ticket-create.ts` (from E48.3) calls `sendEmail()` with `supportTicketReceivedEmail(...)` on every successful insert. `viewToken` parameter is the plain token returned by the RPC (anonymous submitters only); authenticated submitters get a variant without the view link.
- **AC-5:** Reply send is wired in E48.8; resolved is wired in E48.7 (transition button).
- **AC-6:** All templates pass the existing `supportFromAddress` resolution (from `support_config.email` if `enabled=true`, else fall back to `RESEND_DEFAULT_FROM` env). Reply-to header set to `support@subenai.sk` (or env override) for the receipt + resolved emails; reply-to `ticket+{ticketId}@subenai.sk` for the admin-reply email.
- **AC-7:** `Idempotency-Key` header from `email.ts` set to `support-ticket-{ticketId}-{kind}` so a retried submission doesn't double-send the receipt.
- **AC-8:** HTML emails pass `email-test` (lint via existing `tests/functions/email-templates.test.ts` pattern): no unclosed tags, no inline `<script>`, no external resources except the `og:image` from existing infra.

## Open questions

- **Should the email body include the user's own subject/body verbatim (for context)?** *Lean: subject yes, body no.* Body in the receipt is redundant; subject is the disambiguator.
- **HTML-only or HTML+plain-text MIME multipart?** *Lean: multipart.* Improves deliverability scoring.
- **From address — `support@subenai.sk` or `noreply@subenai.sk`?** PLAN Q1 — leans `support@`; needs final confirm in E48 kickoff.
