# E47.1 — Admin documentation pages (20 routes under `/docs/admin/*`)

**Epic:** E47 — Admin self-help (explainers + docs)
**Effort:** `L` (~1 doc page per sprint slot × 20)
**Priority:** `P3`
**Status:** 🟡 Ready
**Branch:** `feature/E47-admin-docs` (to open when work starts)
**Commit prefix:** `feat(docs):`

## Context

E47.0 shipped the `<AdminPageExplainer>` collapsible info panel on
every `/admin/*` menu page (component at
`src/components/admin/AdminPageExplainer.tsx`, i18n content under
`src/i18n/locales/{sk,en,cs}/admin.json` → `explainers.*`). Each
panel's "Documentation" section links to forthcoming long-form pages
under a stable URL scheme:

```
/docs/admin/<sidebar-slug>
```

Until this story ships, those hrefs 404. The Playwright spec
`e2e/specs/admin/page-explainer.spec.ts` only asserts the href
**format** (TC-05), not that the target resolves — so the suite stays
green while the docs are being written. When all 20 docs are live,
TC-05 should be tightened to assert `response.status() === 200`.

## Acceptance criteria

- **AC-1:** All 20 primary `/docs/admin/<key>` routes return HTTP 200
  in production.
- **AC-2:** Each page has an `<h1>` title, a 150–300 word body
  grounded in the existing per-page audit (see commit history of
  `src/i18n/locales/sk/admin.json` for the source material), and a
  "← Back to admin console" breadcrumb link to the matching
  `/admin/<slug>` route.
- **AC-3:** Pages are localised (SK source + EN + CS) using the same
  resolver pattern as `admin.json`. Stub keys are not acceptable —
  every locale ships translated prose, not raw key strings.
- **AC-4:** Cross-cutting doc pages referenced by explainer
  `docs.links` exist as separate routes (or are consolidated into the
  matching primary doc with a stable `#section` anchor — author's
  call, but the href in the explainer must resolve).
- **AC-5:** Playwright spec `e2e/specs/admin/page-explainer.spec.ts`
  TC-05 is tightened: instead of asserting only the href format, it
  follows the link via `page.goto(href)` and asserts
  `response.status() === 200`.
- **AC-6:** Docs are linked from the global help / footer (not just
  from inside the admin explainer) so they are discoverable from
  outside the admin shell.
- **AC-7:** SEO: each page has `<title>` and meta-description
  reflecting its content. Robots = `noindex, follow` (admin
  internals — useful for our team's own search, not for public
  Google).

## Definition of Done

- Implementation: 20 primary + N cross-cutting Markdown routes under

- Tests: TC-05 in `page-explainer.spec.ts` tightened (AC-5).
- Docs: a new top-level `/docs` index page listing every available

- CHANGELOG entry under "Admin / Internal".
- Privacy / cookies docs untouched (no data surface changes).
- Lint 0/0, vitest green, Playwright green on local + CF preview.
- Fresh-context code review.

## Open questions

- **Markdown engine:** which renderer ships these pages? Re-use the
  blog's MDX pipeline (`src/lib/blog/*`), or stand up a lighter
  static-Markdown route under `/docs/`? Decide in a design spike
  before implementation.
- **Authorship model:** are these admin-only docs (gated by AAL2 like
  `/admin/*`) or public-but-noindex? Recommendation: public + noindex
  — keeps the URL shareable in team chats without an extra auth
  bounce.
- **Versioning:** when a doc page's underlying admin feature changes
  (e.g. AI generator gets a runtime toggle), how does the doc get
  bumped? Propose a `lastReviewedAt` field in frontmatter +
  CHANGELOG-grep CI check.
