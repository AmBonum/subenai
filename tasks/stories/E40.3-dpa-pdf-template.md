## Deviations from draft AC (resolved during implementation)

- **Rendering moved CLIENT-SIDE** (not server-side as draft proposed). Matches the existing E38 results-PDF pattern (`@react-pdf/renderer` lazy-imported in the browser). Reasons:
  - PDFKit (the engine behind react-pdf) uses Node streams — CF Workers compatibility is brittle and would inflate the Worker bundle.
  - Single render source for both download AND e-mail (E40.4): client renders once, then optionally POSTs the rendered blob to a follow-up `/api/dpa-email-attach` endpoint.
  - Verified end-to-end in browser preview: `renderDpaPdfBlob()` returns a 24 KB valid PDF with `%PDF-1.3` magic bytes, watermark variant 1.5 KB larger than final.
- **`/api/dpa-request` handler simplified**: no longer returns `pdfBase64`. New response shape `{ ok, requestId, fileName, templateVersion, generatedAt }`. The form locally renders the PDF using these metadata fields.
- **Sub-processor list extracted** to `src/lib/dpa/sub-processors.ts` (3 entries: Supabase, Cloudflare, Resend). Used by both the DPA Annex B table AND the public `/privacy` page (single source of truth — Art. 28(3)(g) compliance).
- **File names** chosen to match repo conventions: `dpa-template.tsx` (parallel to `pdf-document.tsx` from E38) + `render.client.ts` (parallel `pdf-data.ts`). The draft AC's `template-v1.tsx` would have pre-baked the assumption that v2 is also one file; instead a future template revision lands at `dpa-template-v2.tsx` alongside v1, both selectable via `dpa_version`.
- **Template content** is v0.1 DRAFT spanning 6 A4 pages: preamble + parties (1) · Art. 28(3)(a–e) (2) · Art. 28(3)(f–k) (3) · final + signature block (4) · Annex A data categories (5) · Annex B security + sub-processors (6). Watermark "DRAFT — NEZAVÄZUJÚCA UKÁŽKA · NEPODPISOVAŤ" on every page when `isDraft=true`.
- **Draft watermark controllable** via `VITE_DPA_TEMPLATE_DRAFT_WATERMARK` env (defaults `true`). Operator sets it to `"false"` only AFTER legal counsel signs off the template — separate from `dpa_version` bump.
- **Slovak terminology**: uses `prevádzkovateľ` / `sprostredkovateľ` (per Zákon č. 18/2018 Z.z., the Slovak GDPR implementation). The marketing-side `/schools` GDPR card uses the colloquial `kontrolór` — unchanged for consistency with the public-facing copy.

## Context

This is the substance of the epic — a Slovak-language Data Processing Agreement that complies with Art. 28 GDPR, prefilled with the school's data from the intake form, rendered as a multi-page PDF.

The template MUST include all Art. 28(3) mandatory clauses:
- (a) subject-matter, duration, nature and purpose of processing
- (b) types of personal data and categories of data subjects
- (c) obligations and rights of the controller
- (d) the processor processes only on documented instructions
- (e) confidentiality of personnel
- (f) security measures (Art. 32)
- (g) sub-processor authorisation regime
- (h) assistance with data-subject rights
- (i) breach notification + DPIA assistance
- (j) deletion / return of data at end of services
- (k) audit + inspection rights

Plus identifying preamble (controller = school, processor = am.bonum s. r. o.) and signature block.

**This is v0.1 DRAFT. Before the route is flipped on for production (`VITE_DPA_FLOW_ENABLED=true` in CF Pages env), a Slovak lawyer specialising in GDPR must review the template.** The story does not block on legal review — the code ships with a prominent in-PDF watermark "DRAFT — NEZAVÄZUJÚCA UKÁŽKA" until the v1.0 release.

## Acceptance criteria

- **AC-1**: New file `src/lib/dpa/template-v1.tsx` exports a `<DpaDocumentV1 props={DpaTemplateProps}>` react-pdf component. `DpaTemplateProps`:
  ```ts
  type DpaTemplateProps = {
    schoolName: string;
    contactName: string;
    contactEmail: string;
    generatedAt: Date;
    requestId: string;
    isDraft: boolean;  // when true, watermark "DRAFT — NEZAVÄZUJÚCA UKÁŽKA" on every page
  };
  ```
- **AC-2**: New file `src/lib/dpa/render.server.ts` exports:
  - `renderDpaPdfBuffer(props): Promise<Uint8Array>` — uses `@react-pdf/renderer`'s `pdf().toBuffer()` server-side. Returns binary PDF for E40.2's `pdfBase64`.
  - `DEFAULT_TEMPLATE_VERSION` const — `'v0.1'`. Bumps as new template versions ship.
- **AC-3**: Template structure (page layout):
  - **Page 1**: title "Zmluva o spracúvaní osobných údajov (Art. 28 GDPR)"; preamble identifying controller (school name + placeholder for IČO/sídlo) and processor (`am.bonum s. r. o., IČO …, sídlo …`); request ID + generation timestamp.
  - **Page 2–3**: Article-by-article body covering Art. 28(3)(a)–(k). Numbered sections matching the GDPR alpha order.
  - **Page 4**: Sub-processor list (currently: Supabase Inc. — EU region, Cloudflare Inc. — global CDN). Disclosure of where data is hosted.
  - **Page 5**: Annex A — categories of data subjects (žiaci, učitelia, respondenti edu-mode testov); categories of data (meno, e-mail, odpovede, skóre, IP hash, anti-cheat metadáta). Aligns with `/privacy` s4 disclosure.
  - **Page 6**: Annex B — security measures (Art. 32). Mirrors `tasks/stories/E35.1-compliance-audit.md` matrix.
  - **Last page**: Signature block. Two boxes: "Za prevádzkovateľa (škola)" and "Za sprostredkovateľa (am.bonum s. r. o.)". Placeholders for date + signature + meno tlačeným písmom + funkcia.
- **AC-4**: Visual polish:
  - Same `PALETTE` + `<StyleSheet>` patterns as [pdf-document.tsx](../../src/lib/edu/pdf-document.tsx). Brand-consistent.
  - Page footer with "subenai DPA v0.1 · strana {n}/{total}".
  - Watermark (when `isDraft=true`): diagonal text "DRAFT — NEZAVÄZUJÚCA UKÁŽKA · NEPODPISOVAŤ", 40% opacity, behind body content.
- **AC-5**: File-size budget: rendered PDF for a typical school payload < 200 KB. Verify via test. If we go over, embed-only base fonts (no custom font files), no images.
- **AC-6**: `src/lib/dpa/render.server.ts` is server-only — guarded by a `// @ts-expect-error server-only` import directive so the bundler does not pull react-pdf into the client bundle. Verify via `npm run build` + a bundle size diff.
