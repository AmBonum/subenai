## Context

The user explicitly asked for tests across security, integration, and
e2e layers, with test data seeded via SQL and cleanup after each run.
This story is the consolidation point — individual stories above land
their own Vitest + Playwright specs; this story adds the cross-cutting
suite plus the canonical seed/cleanup scripts that the e2e specs
reuse.

PLAN §"Security review checklist" enumerates the security suite's
checklist.

## Acceptance criteria

- **AC-1:** Seed script `supabase/scripts/seed-e48-tickets.sql` (idempotent, `ON CONFLICT DO NOTHING`):
  - 1 anonymous ticket (`new`, no attachments)
  - 1 anonymous ticket with one clean image attachment
  - 1 anonymous ticket with one sanitisation-error attachment (mocked via direct INSERT with `scan_status='error'`)
  - 1 authenticated ticket from `audit-bot@subenai.test` user (`in_progress`)
  - 1 ticket with a multi-message thread (user + admin + user)
  - 1 archived ticket
  - 1 resolved ticket > 90 days old (for auto-archive cron test)
  - All test rows tagged with `subject LIKE 'E48_TEST_%'` for cleanup
- **AC-2:** Cleanup script `supabase/scripts/cleanup-e48-tickets.sql`:
  - `DELETE FROM support_ticket_attachments WHERE ticket_id IN (SELECT id FROM support_tickets WHERE subject LIKE 'E48_TEST_%')`
  - `DELETE FROM support_ticket_messages WHERE ticket_id IN (...)`
  - `DELETE FROM support_tickets WHERE subject LIKE 'E48_TEST_%'`
  - Storage objects cleanup via `storage.objects` DELETE WHERE `bucket_id='support-attachments' AND name LIKE 'E48_TEST_%'`
- **AC-3:** Vitest contract suite (one file per concern):
  - `tests/db/support-tickets-schema.test.ts` (already in E48.1)
  - `tests/db/support-tickets-rls-lockdown.test.ts` (already in E48.1) — extended here with fuzz cases
  - `tests/db/support-tickets-cron-auto-archive.test.ts` — verifies the cron's worker function selects the right candidate rows
  - `tests/db/support-attachments-storage-policies.test.ts` — verifies the bucket RLS denies anon SELECT, anon INSERT, anon DELETE, and only admin SELECT works
- **AC-4:** Vitest functions suite:
  - `tests/functions/support-attachment-upload.test.ts` (already in E48.2)
  - `tests/functions/support-attachment-scan.test.ts` (already in E48.2)
  - `tests/functions/support-ticket-create.test.ts` (already in E48.3)
  - `tests/functions/support-ticket-reply.test.ts` (already in E48.8)
  - `tests/functions/support-notify-admin.test.ts` (already in E48.9)
- **AC-5:** Vitest integration suite (`e2e/integration/support/`):
  - `attachment-pipeline.spec.ts` (already in E48.2) — real Supabase, full sanitisation + scan round-trip
  - `submit-and-receive-email.spec.ts` — uses service-role client to insert a ticket via the RPC, asserts Resend dashboard event exists (mocked via a captured webhook or a known idempotency key)
- **AC-6:** Playwright e2e suite (`e2e/specs/support/`):
  - `kontakt-anonymous-submission.spec.ts` (already in E48.3) — anonymous happy path with Turnstile mocked
  - `app-help-contact-submission.spec.ts` (already in E48.4) — authenticated path
  - `admin-tickets-index.spec.ts` (already in E48.6)
  - `admin-ticket-detail.spec.ts` (already in E48.7)
  - `admin-notification-prefs.spec.ts` (already in E48.9)
  - **NEW** `support-end-to-end.spec.ts` — single integration scenario: anonymous user submits, admin gets in-app notification, admin replies, user receives email (via Resend test inbox capture). Seeds from `seed-e48-tickets.sql`; cleans up via `cleanup-e48-tickets.sql` in `afterAll`.
- **AC-7:** Security suite — new file `tests/security/support-ticket-fuzz.test.ts`:
  - 100 randomly-generated submission payloads → none cause 5xx
  - SQL-injection bait in subject + body → all neutralised (Postgres prepared statements)
  - XSS bait (`<script>alert(1)</script>`, `<img onerror=…>`, `<svg onload=…>`) in body → admin UI renders text-safe
  - Path traversal in attachment filename (`../../etc/passwd`) → rejected at sanitisation
  - MIME confusion (file claims `image/png`, magic bytes are HTML) → rejected
  - JWT tampering (modified `aal` claim, modified `role` claim) → 401
  - View-token replay (use the same token for a different ticket id) → 403
  - Rate limit bypass attempts (rotating IPs via `X-Forwarded-For` header injection) → still rate-limited per CF KV bucketing
- **AC-8:** Playwright POMs created:
  - `e2e/poms/support/KontaktPage.ts`
  - `e2e/poms/support/KontaktOdoslanePage.ts`
  - `e2e/poms/support/KontaktTicketPage.ts`
  - `e2e/poms/app/AppHelpLandingPage.ts`
  - `e2e/poms/app/AppHelpContactPage.ts`
  - `e2e/poms/admin/AdminTicketsIndexPage.ts`
  - `e2e/poms/admin/AdminTicketDetailPage.ts`
  - `e2e/poms/admin/AdminNotificationPrefsPage.ts`
  - Per CLAUDE.md: specs only use POM getters; no direct `page.locator(...)`.
