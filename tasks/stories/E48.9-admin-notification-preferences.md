## Context

Per the user's brief: admins can switch notifications on/off globally AND
per category. Channels: e-mail (Resend) + in-app (existing `notifications`
table + new Supabase Realtime channel). Sidebar badge counter shows unread
admin notifications.

PLAN §"Architecture > Notification flow" + §"Decision D-5" specify the
behaviour.

## Acceptance criteria

- **AC-1:** Route `src/routes/admin/settings/notifications.tsx`. Admin + AAL2 gate. Sidebar entry under "Nastavenia" (existing /admin/settings parent).
- **AC-2:** UI shows for the current admin:
  - **Master switch** — "Dostávať upozornenia z podpory" (boolean toggle)
  - **Channels** — checkboxes: "E-mail" + "V aplikácii"
  - **Cadence** — radio: `Okamžite | Hodinový digest | Denný digest | Vypnuté`
  - **Per-category table** — 7 rows (one per category enum value), each with a Slovak label + an on/off toggle
  - "Uložiť zmeny" button — sticky bottom bar appears when state is dirty; on save: `UPSERT admin_notification_preferences (user_id, ...) VALUES (...) ON CONFLICT (user_id) DO UPDATE`. Toast: "Nastavenia upozornení boli uložené."
- **AC-3:** Database trigger on `support_tickets` INSERT fires `pg_notify('support_tickets_admin', payload)` where payload is `{ id, status, category, subject, submitter_email, created_at }`.
- **AC-4:** The admin shell (`/admin/_layout.tsx` or equivalent) subscribes to Supabase Realtime channel `support_tickets_admin`. On `INSERT` events:
  - Look up the current admin's `admin_notification_preferences`
  - If `enabled === false` OR `per_category[category] === false` OR `channels.in_app === false` → skip in-app
  - Else: insert into `notifications` with `event_type='support_ticket_new'`, payload = subject + ticketId; increment the sidebar badge counter; show a toast "Nová žiadosť: {subject}"
- **AC-5:** Server-side dispatcher (pg_cron job `support-notify-admins` every minute):
  - For each unprocessed `notifications` row of type `support_ticket_*`: select admins whose `channels.email === true` AND `per_category[category] === true` AND `enabled === true`. For each admin, dispatch via `/functions/api/support-notify-admin.ts` respecting `digest_cadence`:
    - `instant` → fire immediately
    - `hourly` → batch every hour at :00
    - `daily` → batch every day at 09:00 Europe/Bratislava
    - `off` → skip
  - Mark processed via `notifications.delivered_at`
- **AC-6:** Sidebar badge in `AdminSidebar.tsx` shows count of unread `notifications` rows where `event_type LIKE 'support_ticket_%'` AND `read_at IS NULL` for the current admin. Click on the sidebar entry "Podpora" marks all support-related notifications read for this admin.
- **AC-7:** Lazy-creation of preferences row: first time an admin opens `/admin/settings/notifications`, if no row exists, insert with defaults (enabled=true, channels={email:true,in_app:true}, per_category={all:true}, cadence='instant').
- **AC-8:** Test IDs: `admin-notif-master-toggle`, `admin-notif-channel-email`, `admin-notif-channel-inapp`, `admin-notif-cadence-{value}`, `admin-notif-cat-{category}-toggle`, `admin-notif-save`, `admin-notif-saved-toast`, `admin-sidebar-support-badge`.
- **AC-9:** Realtime fallback: if the channel goes `CLOSED` (network blip), poll `notifications` every 60s. UI shows a discreet "offline" indicator if > 2min disconnected.
