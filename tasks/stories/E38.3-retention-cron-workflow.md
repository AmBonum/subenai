# E38.3 — GitHub Actions retention-cron workflow

**Epic:** [E38 — Retention crons + auto-anonymisation](../PLAN-2026-05-20-E38-retention-crons.md)
**Effort:** `M` (≤ 2 days)
**Priority:** `P1`
**Status:** 🟡 Ready

## Context

Supabase Free tier has no `pg_cron`. We need an external scheduler
that calls our three retention RPCs daily. Decision (PLAN D1): use
GitHub Actions `schedule:` cron. We already run 4 scheduled workflows
on the same infra (CI, CodeQL, npm-audit, ZAP), so this is zero new
infrastructure.

The workflow runs once daily at 03:00 UTC, instantiates a Supabase
client with `SUPABASE_SERVICE_ROLE_KEY` (repo secret), and calls the
three RPCs sequentially. Result counts are logged.

## Acceptance criteria

- **AC-1**: New file `.github/workflows/retention-cron.yml`:
  - Triggers: `schedule: '0 3 * * *'` + `workflow_dispatch`.
  - Job runs on `ubuntu-latest`, timeout 10 min.
  - `permissions: contents: read` only.
  - Step 1: checkout (so we have `scripts/run-retention.mjs`).
  - Step 2: `node scripts/run-retention.mjs`.
  - Env: `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` from secrets.
- **AC-2**: New file `scripts/run-retention.mjs`:
  - Reads env vars, validates they're present.
  - Instantiates `@supabase/supabase-js` with service-role key.
  - Calls `purge_expired_attempts()`, then
    `anonymize_expired_anticheat()`, then
    `anonymize_expired_edu_respondents()` via `.rpc()`.
  - Logs each result count.
  - Exits non-zero on any RPC error.
- **AC-3**: `package.json` adds the script entry
  `"retention:dry-run": "DRY_RUN=1 node scripts/run-retention.mjs"` so
  an operator can validate config locally.
- **AC-4**: Script supports `DRY_RUN=1` mode that connects + lists the
  RPC names it would call, without invoking them.
- **AC-5**: Workflow logs are publicly visible per the existing GHA
  policy; no PII leaks in log output (RPC return is a count, not row
  data — verify this in test).
- **AC-6**: Documented in the runbook (E38.5) how to set the
  `SUPABASE_SERVICE_ROLE_KEY` repo secret (it should already exist
  from E35.7 era).
