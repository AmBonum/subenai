# E40.2 — `/schools/dpa` route + intake form + server function (download path)

**Epic:** [E40 — DPA automation](../PLAN-2026-05-20-E40-dpa-automation.md)
**Effort:** `M` (≤ 2 days)
**Priority:** `P1`
**Status:** 🟡 Ready

## Context

Replace the legacy `mailto:` CTA on `/schools` ([SchoolsGdprCard.tsx:85-91](../../src/components/schools/SchoolsGdprCard.tsx:85)) with a real intake flow. The user lands on `/schools/dpa`, fills three fields + a consent checkbox, submits, and gets the DPA PDF as an instant browser download. E-mail delivery (the secondary channel) lives in E40.4.

Form UX mirrors the existing respondent intake pattern at [IntakeStep.tsx](../../src/components/respondent/IntakeStep.tsx) — same validation cadence, same Slovak microcopy tone, same test-id naming convention but prefixed `schools-dpa-form-*`.

## Acceptance criteria

- **AC-1**: New route file `src/routes/schools.dpa.tsx`:
  - Public route, no auth gate.
  - Head: `<title>Žiadosť o DPA — subenai</title>` + canonical URL + `og:` meta. No JSON-LD needed (transactional page, not browseable content).
  - Layout: same `max-w-2xl mx-auto px-4 py-12` shell as other forms; renders `<SchoolsDpaForm />`.
  - Behind feature flag `VITE_DPA_FLOW_ENABLED` — when `false`, the route returns a 200 with copy "DPA tok je aktuálne v príprave; napíšte nám na kontakt@subenai.sk." (manual fallback during legal review).
- **AC-2**: New component `src/components/schools/SchoolsDpaForm.tsx`:
  - Three fields: `contact_name`, `contact_email`, `school_name` — all required.
  - One checkbox: `consent_dpa_processing` — required, labelled "Súhlasím so spracovaním vyššie uvedených údajov za účelom vyhotovenia DPA podľa čl. 6 ods. 1 písm. b) GDPR (predzmluvné opatrenia)."
  - Cloudflare Turnstile widget embedded ([@marsidev/react-turnstile](https://github.com/marsidev/react-turnstile) or vanilla `<script>` — pick the smaller bundle). Site key from `VITE_TURNSTILE_SITE_KEY`. Token submitted with the form payload.
  - Submit button disabled until all required fields valid AND consent checked AND Turnstile token present.
  - Test-ids: `schools-dpa-form-name`, `schools-dpa-form-email`, `schools-dpa-form-school`, `schools-dpa-form-consent`, `schools-dpa-form-turnstile`, `schools-dpa-form-submit`, `schools-dpa-form-status` (the live region for success / error messages).
  - On submit: calls `requestDpa` server function, then triggers a download via `URL.createObjectURL(blob)` + a temporary `<a download="DPA-subenai-{school-slug}-v{version}.pdf">`. The success state shows: "PDF sa stiahlo. Kópiu sme poslali aj na {email}." (or, if email failed, the same line without the second sentence — see E40.4 for the failure path).
- **AC-3**: New server function `src/lib/dpa/request-dpa.server.ts` exposed via TanStack Start `createServerFn`:
  - Zod schema validates payload (`contact_name`: 2–120 chars, `contact_email`: RFC-compliant + max 254, `school_name`: 2–200 chars, `consent_dpa_processing`: literal `true`, `turnstile_token`: non-empty string).
  - **Verifies Turnstile token** by POSTing to `https://challenges.cloudflare.com/turnstile/v0/siteverify` with `TURNSTILE_SECRET_KEY`. Rejects on failure with 400 + `error: 'bot_challenge_failed'`.
  - Rejects if any other field fails — returns 400 with a structured error.
  - Hashes the client IP (sha256, salted) → `ip_hash` on the row.
  - Rate-limit: max 3 requests per `ip_hash` per 15 min (in-memory LRU on the worker is fine for v1 — Redis is over-engineering). Defence-in-depth on top of Turnstile.
  - INSERTs row in `dpa_requests` via Supabase service-role client. `dpa_version` from `DEFAULT_TEMPLATE_VERSION` const (= `'v0.1'` initially).
  - Calls `renderDpaPdfBuffer({ schoolName, contactName, contactEmail, version })` (stub — actual implementation lands in E40.3).
  - Returns `{ pdfBase64, fileName, requestId }`.
  - On Supabase / render error: logs, returns 500 with safe message ("Vyhotovenie DPA zlyhalo, skús to znova."). The client surfaces this in the live region.
- **AC-4**: [SchoolsGdprCard.tsx](../../src/components/schools/SchoolsGdprCard.tsx) CTA changes:
  - Replace `<a href={mailto:...}>` with `<Link to="/schools/dpa">` when `import.meta.env.VITE_DPA_FLOW_ENABLED === 'true'`.
  - Fallback to existing mailto when flag is `false` or unset.
  - Test-id `schools-gdpr-dpa-link` preserved (existing test at [SchoolsGdprCard.test.tsx](../../tests/components/schools/SchoolsGdprCard.test.tsx) must still pass).
- **AC-5**: i18n keys added to `src/i18n/locales/sk/marketing.json` under `skoly_dpa.*`:
  - `page_title`, `intro`, `field_name_label`, `field_email_label`, `field_school_label`, `consent_label`, `submit_button`, `success_with_email`, `success_no_email`, `error_generic`, `error_rate_limit`, `feature_disabled`.
