## Context

Phase 2 prepína detail testu z read-only do password-locked. Schéma už má
`tests.password_hash` (od AH-1.4), takže pridávame iba jeden stĺpec
(`password_hash_version`) a tri RPC funkcie pre set / clear / verify —
zrkadlové na `hash_test_set_password` z edu modu (20260501000000_edu_mode.sql).

## Akceptačné kritériá

- **AC-1:** Migrácia `supabase/migrations/20260521220000_test_password_v2.sql`
  existuje, je idempotentná (`IF NOT EXISTS`, `DROP FUNCTION IF EXISTS`),
  pridáva stĺpec `password_hash_version INT NOT NULL DEFAULT 0` a
  vykoná backfill na hodnotu `1` pre existujúce riadky s `password_hash IS NOT NULL`.
- **AC-2:** `hash_test_password(test_id, password)` RPC — SECURITY DEFINER,
  body-level owner check (T14), min 8 / max 256 znakov (T8), bcrypt cez
  `gen_salt('bf', 10)`, hash-prefix guard ($2a$/$2b$/$2y$ — T4), bump
  `password_hash_version`, audit_log INSERT v tej istej TX (T6).
  `REVOKE FROM PUBLIC, anon, authenticated`.
- **AC-3:** `clear_test_password(test_id)` RPC — paralela k hash_test_password,
  nastaví `password_hash = NULL`, bumpne pv, audit s `{op: 'clear'}`.
  `REVOKE FROM PUBLIC, anon, authenticated`.
- **AC-4:** `verify_test_password(p_share_id, p_password)` RPC —
  `RETURNS TABLE(verified bool, current_pv int)`. Anon-callable
  (`GRANT EXECUTE TO anon, authenticated`) — front door je CF function
  rate-limit. Pri NULL hash vracia `(false, COALESCE(pv, 0))` — rovnaký
  shape pre absent-share / no-password / wrong-password, oracle uzavretý
  jitterom v CF funkcii.
- **AC-5:** `DEPLOY_SETUP.sql` mirror identický s migráciou.
- **AC-6:** `src/integrations/supabase/types.ts` rozšírený o nový stĺpec
  + 3 nové RPC types (`hash_test_password`, `clear_test_password`,
  `verify_test_password`).
