# E45.8 — Queries: `useSetTestPassword`, `useClearTestPassword`, `has_password`

**Epic:** [E45](../PLAN-2026-05-21-E45-test-detail-editor.md)
**Effort:** `S`
**Status:** ✅ Done
**Commit prefix:** `feat(queries):`

## Akceptačné kritériá

- **AC-1:** `useSetTestPassword(testId)` volá RPC `hash_test_password`, vracia
  nový `password_hash_version`. Invalidatuje `["user","tests",testId]` aj
  `["user","tests"]`.
- **AC-2:** `useClearTestPassword(testId)` volá RPC `clear_test_password`,
  vracia nový pv, invalidatuje rovnaké queries.
- **AC-3:** `Test` interface v `lib/platform/types.ts` má nové polia
  `has_password: boolean` (kanonický UI flag, derivované z `password_hash !== null`)
  a `password_hash_version: number`. Pôvodný `password` field je zachovaný
  ako *DEPRECATED* pre back-compat (`null | ""` strings — nikdy
  neexponujeme hash na klient).
- **AC-4:** `mapTest` v `queries.ts` neexponuje raw hash — pri non-NULL
  hash vracia prázdny string `""` (sentinel), `has_password = true`.
  Defense-in-depth voči akcidentálnemu leak do DOM / logov.
- **AC-5:** `SEED_TESTS` + `mock-store.createTest` populujú obe nové polia
  konzistentne s `password`.
