## Implementation notes

- Postgres `uuid` columns don't support `LIKE`, so the teardown uses an explicit ID set built from the fixtures module. Cleanup ordering: `session_answers → sessions → test_questions → tests → questions → audit_log (by actor_id)`.
- The pw-protected fixture stores a bcrypt hash inline in the SQL. The plaintext is documented in `e49-fixtures.ts`; rotating the hash requires regenerating both sides in lockstep.
- The seed SQL is `psql`-compatible (single `BEGIN ... COMMIT` block, no `\meta` commands) so it can be pasted verbatim into the Supabase dashboard SQL editor for prod-side execution.
- `E49_DROP_USERS=1` toggle in teardown drops the four TU-* auth.users via the admin client. Default-off because auth provisioning is rate-limited; keeping users between runs is cheap.
