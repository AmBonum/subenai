# E48.7 — `/admin/tickets/$ticketId` detail — thread, reply, status transitions, scan-gated downloads

**Epic:** E48 — Support contact form + admin ticketing system
**Effort:** `M` (~2 days)
**Priority:** `P0`
**Status:** 🟡 Ready
**Branch:** `feature/E48-support-ticketing`
**Commit prefix:** `feat(admin):`
**Dependencies:** E48.1, E48.6 (parent index). E48.8 wires the actual reply send.

## Context

The single most-used admin page in the epic. Sticky header with ticket
metadata + action toolbar; scrollable thread below; sticky reply
composer at the bottom. Slovak labels. ConfirmDialog for every state
transition that's non-reversible.

PLAN §"UI — surface inventory > Admin" + §"Decisions D-8, D-9" pin the
behaviour.

## Acceptance criteria

- **AC-1:** Route `src/routes/admin/tickets/$ticketId.tsx`. Same admin + AAL2 gate.
- **AC-2:** Sticky header showing:
  - Subject (h1)
  - Status badge + category badge
  - Submitter name + email (link to `/admin/users/$id` if applicable)
  - Created at + last updated at
  - Assigned-to avatar + change button
  - Action toolbar buttons (see AC-4)
  - Audit timeline collapsible (last 20 status transitions for this ticket)
- **AC-3:** Thread (scrollable mid-section). Messages rendered chronologically: user messages aligned left (avatar circle with initials), admin messages aligned right (admin avatar + name + badge). Each message: body (line-break preserved, no Markdown rendered), timestamp, attachments (chip-style with filename + size + scan-status badge — only clean attachments are clickable to download).
- **AC-4:** Status transition buttons in the action toolbar:
  - "Začať riešiť" (`new` → `in_progress`) — simple confirm
  - "Čakám na používateľa" (`in_progress` → `waiting_user`) — silent, no confirm
  - "Uzavrieť" (any → `resolved`) — `ConfirmDialog` `severity='success'`. On confirm: status update + auto-send `supportTicketResolvedEmail` to submitter.
  - "Znovu otvoriť" (`resolved`/`archived` → `in_progress`)
  - "Archivovať" (`resolved` → `archived`) — `ConfirmDialog` `severity='warning'`
  - "Vymazať natvrdo" — `ConfirmDialog` `severity='destructive'` with `typedConfirm={{ expected: ticket.subject.slice(0, 30), label: "Zadajte prvých 30 znakov témy" }}`. On confirm: soft-delete (`deleted_at = now()`) with 5-min grace per E46.5 cron pattern; admin sees a "Zrušiť mazanie" banner during the window. After 5 min, pg_cron hard-deletes the row + Storage objects.
- **AC-5:** Reply composer at the bottom (sticky):
  - Textarea (1–10000 chars, live counter)
  - "Pripojiť súbor" button (admin attachments allowed — same sanitisation pipeline)
  - "Odoslať odpoveď" button — calls `/functions/api/support-ticket-reply.ts` (E48.8). On send: appends to thread; flips status to `waiting_user`; sends email via `supportTicketReplyEmail`.
  - Templates dropdown (canned responses — out of scope this story; placeholder UI only).
- **AC-6:** Attachment download — clicking a `clean` attachment chip calls `request_attachment_signed_url(p_attachment_id)` RPC, opens the resulting signed URL in a new tab with `Content-Disposition: attachment` (forced download, never inline render). Audit-logged.
- **AC-7:** Sanitisation-error attachments (`scan_status='error'`) render with an amber warning icon, tooltip "Súbor nemohol byť bezpečne spracovaný a nebol uložený. Požiadajte používateľa o iný formát." (this should be rare — sanitisation errors normally fail the upload before a row is inserted; the `error` state is only used for the post-hoc edge case of admin-uploaded files that fail late). No deterministic-only file ever reaches the admin without `scan_status='clean'`.
- **AC-8:** Audit log of every state transition + every attachment download + every reply send. Audit row payload: `{ actor_id, ticket_id, action, from_status?, to_status?, attachment_id? }`.
- **AC-9:** Test IDs: `admin-ticket-header-subject`, `admin-ticket-header-status-badge`, `admin-ticket-action-start`, `admin-ticket-action-waiting`, `admin-ticket-action-resolve`, `admin-ticket-action-reopen`, `admin-ticket-action-archive`, `admin-ticket-action-delete`, `admin-ticket-reply-textarea`, `admin-ticket-reply-attach-button`, `admin-ticket-reply-send`, `admin-ticket-attachment-{attachmentId}`, `admin-ticket-cancel-deletion-banner`.
- **AC-10:** Realtime — if another admin replies or transitions status while this admin has the page open, the page updates in place (via the existing realtime channel from E48.9). Toast: "{Iný admin} odpovedal".
