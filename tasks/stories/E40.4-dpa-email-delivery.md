# E40.4 — Resend integration + e-mail delivery + status tracking

**Epic:** [E40 — DPA automation](../PLAN-2026-05-20-E40-dpa-automation.md)
**Effort:** `M` (≤ 2 days)
**Priority:** `P1`
**Status:** 🟡 Ready

## Context

The instant-download path (E40.2) already gives the user the DPA PDF in their browser. This story adds the secondary channel: send the same PDF as an e-mail attachment to the address the user entered. The e-mail also serves as proof-of-delivery (operator can answer "did the school actually receive it?") and as the conversational thread for follow-up signature.

E-mail failure does NOT break the user flow — the download already happened. Failure is logged on the `dpa_requests` row (`email_status='failed'`, `email_error` populated). Admin can manually re-send from the panel in E40.5.

## Acceptance criteria

- **AC-1**: New dependency `resend` in `package.json` (current latest stable, pinned). No transitive vulnerabilities (`npm audit` clean before merge).
- **AC-2**: New module `src/lib/dpa/email.server.ts`:
  - Exports `sendDpaEmail({ to, schoolName, pdfBuffer, requestId, version }): Promise<{ ok: true, messageId: string } | { ok: false, error: string }>`.
  - Reads `RESEND_API_KEY` from `process.env`. Throws a typed config error at boot if missing in production (`NODE_ENV=production` AND key absent → loud failure in CF Pages worker logs).
  - Subject: `"subenai — DPA pre školu {schoolName}"` (Slovak).
  - From: `noreply@subenai.sk` (per decision D2 — confirm with operator before go-live).
  - HTML body: short Slovak intro ("Posielame DPA pre {schoolName} podľa žiadosti z {date}.") + plain CTA "Po podpise nám pošlete sken / scan na kontakt@subenai.sk". Plain-text fallback emitted from the same source.
  - Attachment: `DPA-subenai-{schoolSlug}-{version}.pdf` (matches the download filename in E40.2).
- **AC-3**: `src/lib/dpa/request-dpa.server.ts` (from E40.2) extended:
  - After successful DB insert + render, calls `sendDpaEmail`.
  - On success: UPDATE row with `email_status='sent'`, `email_message_id={messageId}`.
  - On failure: UPDATE row with `email_status='failed'`, `email_error={truncated msg, max 500 chars}`. Returns the download blob anyway (success).
  - Both INSERT and UPDATE happen in a single transaction is preferred — at minimum, the UPDATE swallows its own error (logs but doesn't fail the user request).
- **AC-4**: New env vars documented in `.env.example`:
  - `RESEND_API_KEY=re_xxx` (required in production)
  - `DPA_EMAIL_FROM=noreply@subenai.sk` (defaults to this if unset)
- **AC-5**: New repo secret `RESEND_API_KEY` provisioned in:
  - Cloudflare Pages env (production + preview)
  - GitHub Actions secrets (for any CI test that exercises the e-mail path with a stub)
  - Documented in [tasks/E40-runbook.md](./E40-runbook.md) (the runbook from E40.3).
- **AC-6**: Test mode — when `process.env.RESEND_API_KEY` starts with `re_test_` or is unset in `NODE_ENV=test`, `sendDpaEmail` returns `{ ok: true, messageId: 'test-stub' }` without calling Resend. Real key in production / preview.
