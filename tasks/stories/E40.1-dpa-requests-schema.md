## Context

The DPA intake flow needs a place to persist who asked for a DPA, when, and for which school. Mirrors the existing `dsr_requests` shape (admin queue table) so the admin panel work in E40.5 can reuse the same patterns. The 12-month PII anonymisation is exposed as a new RPC that plugs into the existing E38 retention cron.

## Acceptance criteria

- **AC-1**: New migration `supabase/migrations/{timestamp}_dpa_requests.sql` creates:
  ```sql
  CREATE TABLE public.dpa_requests (
    id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    created_at    timestamptz NOT NULL DEFAULT now(),
    downloaded_at timestamptz,
    contact_name  text,
    contact_email text,
    school_name   text NOT NULL,
    dpa_version   text NOT NULL,
    status        text NOT NULL DEFAULT 'pending'
                   CHECK (status IN ('pending', 'delivered', 'signed', 'cancelled')),
    email_status  text DEFAULT 'pending'
                   CHECK (email_status IN ('pending', 'sent', 'failed')),
    email_error   text,
    ip_hash       text,
    anonymized_at timestamptz
  );
  ```
- **AC-2**: RLS enabled. Two policies (revised from draft):
  - `dpa_requests_admin_read` — `SELECT` allowed only when `public.has_role(auth.uid(), 'admin')` returns true.
  - `dpa_requests_admin_update` — `UPDATE` (status flips, manual anonymise) allowed only for admin.
  - **No INSERT policy** — INSERTs flow exclusively through the server function (E40.2) using the service-role client. This matches the existing `dsr_requests` pattern (admin-hub schema AH-1.5). Revised from the draft that exposed an anon INSERT policy: the server function is the only validation gate (Turnstile + Zod + rate-limit) and goes via service-role, so an anon write path would be redundant attack surface.
  - No `DELETE` policy → rows are immutable except via anonymisation; admin removes by anonymising.
- **AC-3**: New function `public.anonymize_expired_dpa_requests()` — `SECURITY DEFINER`, idempotent. NULLs `contact_name` + `contact_email`, sets `anonymized_at = now()`, on rows where `created_at < (now() - interval '12 months')` AND `anonymized_at IS NULL`. Returns count of affected rows.
- **AC-4**: Indexes:
  - `dpa_requests_created_at_idx` on `created_at DESC` (admin panel pagination).
  - `dpa_requests_school_name_trgm_idx` GIN trigram (admin search by school).
- **AC-5**: `src/integrations/supabase/types.ts` regenerated in the same commit to include the new table + RPC signature. Verify the file under `Database['public']['Tables']['dpa_requests']` and `Database['public']['Functions']['anonymize_expired_dpa_requests']`.
- **AC-6**: New migration appended to `DEPLOY_SETUP.sql` in the same order (the standalone bootstrap file ships every migration since AH-1).
