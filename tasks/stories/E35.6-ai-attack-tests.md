# E35.6 — AI-attack & anti-automation suite

**Epic:** [E35 — Security & GDPR compliance audit + test coverage expansion](../PLAN-2026-05-20-E35-security-compliance-audit.md)
**Effort:** `M` (≤ 2 days)
**Priority:** `P2` (should)
**Status:** 🟡 Ready

## Context

The recon flagged five concrete AI-related threats specific to an IQ
leaderboard product:

1. AI-driven test farming via headless browsers (no detection today).
2. Question-bank scraping (questions cached client-side, no rotation).
3. Distributed rate-limit bypass (current limits: 3/5min/IP on
   `begin-edu-attempt`, 6/5min/IP on `finish-edu-attempt`).
4. Prompt injection on the future `/api/admin/ai-generate` endpoint
   (AH-11, not yet wired) via the `topic` field.
5. `robots.txt` and `noindex` policy drift letting LLM crawlers
   ingest question content.

This story covers the *test* side at zero extra cost. Implementation
fixes (Turnstile on quiz routes, behavioural defence, question
rotation) become E40.

## User story

> As the operator, **I want** automated coverage of the current
> anti-automation surface and a harness ready for the AH-11 backend,
> **so that** any regression in rate limits, robots policy, or future
> AI generator behaviour fails CI loudly.

## Acceptance criteria

- **AC-1**: New `specs/security/ai-attack-surface.md` test plan in
  English describes each scenario below.
- **AC-2**: New `tests/security/rate-limit-contract.test.ts` imports
  the rate-limit primitives from `functions/_lib/security.ts` and
  asserts the bucket maths match the documented env defaults
  (`PORTAL_LINK_PER_IP_PER_HOUR=10`,
  `PORTAL_LINK_COOLDOWN_SECONDS=900`,
  `PORTAL_LINK_DAILY_CAP=200`, edu attempt 3/5min/IP + 50/h/set,
  finish 6/5min/IP). Locks values so a silent env change breaks CI.
- **AC-3**: New `tests/security/question-bank-exposure.test.ts`
  mounts the quiz component with a known fixture and asserts the
  correct-answer index field is **not** present in the client-side
  React state / props for the active question. Expected-red allowed
  if the gap exists — that red maps to E40.
- **AC-4**: New `e2e/specs/security/headless-load.spec.ts` issues
  4 rapid `POST /api/begin-edu-attempt` requests from one Playwright
  client and asserts the 4th returns HTTP 429.
- **AC-5**: New `e2e/specs/security/robots-crawl.spec.ts`:
  - Fetches `/robots.txt` and asserts disallow rules for `/t/`,
    `/r/`, `/admin/`, `/test/builder/`, `/app/`, `/login`, `/auth/`.
  - Fetches the rendered HTML of one `/t/$shareId` route and asserts
    `<meta name="robots" content="noindex,nofollow">` is present.
- **AC-6**: New `e2e/specs/security/agent-detection.spec.ts`
  navigates with `navigator.webdriver === true` (default Playwright
  behaviour) and asserts the app still serves normally. Test name
  is explicit: `should not block headless browsers (current
  behaviour — see E40 for follow-up)`. Documents the current state
  so any future detection landing without test update is visible.
- **AC-7**: `tests/security/prompt-injection-harness.test.ts`
  (already created in E35.3) extends with payloads specific to the
  AH-11 `topic` field — long inputs, control chars, jailbreak
  attempts, prompt-escape patterns from `prompt-injection-payloads.ts`.
