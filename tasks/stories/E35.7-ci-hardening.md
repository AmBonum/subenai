# E35.7 — CI hardening (free-tier only)

**Epic:** [E35 — Security & GDPR compliance audit + test coverage expansion](../PLAN-2026-05-20-E35-security-compliance-audit.md)
**Effort:** `S` (≤ ½ day)
**Priority:** `P2` (should)
**Status:** ✅ Files ready — separate `npm-audit.yml` workflow chosen instead of touching `ci.yml` (zero-risk additive path)

## Context

CI today runs lint, Vitest, build (`.github/workflows/ci.yml`) and
selective Playwright (`.github/workflows/e2e.yml`). It does **not**:
- Run any SAST.
- Block on known-vulnerable transitive dependencies.
- Auto-update outdated dependencies.
- Scan for secrets in the diff.

The user's constraint is **free-tier only**. GitHub-native tooling
(CodeQL, Dependabot, Secret scanning) covers four of those four with
zero recurring cost.

## User story

> As the operator, **I want** the CI to catch dependency vulns,
> obvious code-injection patterns, and stale dependencies before
> they ship, **so that** "security" isn't a quarterly ritual but a
> per-PR signal.

## Acceptance criteria

- **AC-1**: New `.github/workflows/codeql.yml` — GitHub CodeQL Action,
  `javascript`, `typescript` languages, weekly schedule + on push to
  `main` + on PRs touching `src/**` or `functions/**`. Uses the
  default `security-and-quality` query suite. `paths-ignore` covers
  `**/*.md`, `docs/**`, `tasks/**`, `specs/**`.
- **AC-2**: New `.github/dependabot.yml`:
  - `npm` ecosystem, daily schedule, grouped minor/patch updates,
    individual PRs for major.
  - `github-actions` ecosystem, weekly schedule.
  - Reviewers / assignees blank (GitHub assigns to `CODEOWNERS`).
- **AC-3**: ~~Modify `.github/workflows/ci.yml` to add a step~~ —
  **Changed**: created **separate** `.github/workflows/npm-audit.yml`
  workflow instead. Same `npm audit --omit=dev --audit-level=high`
  command, but in its own job so it doesn't gate unrelated PRs.
  Rationale: zero-risk additive — existing `ci.yml` stays untouched,
  npm audit failures don't block build correctness signal.
- **AC-4**: GitHub Secret scanning + push protection enabled in
  repo settings. **This is a UI-only setting on github.com**, not a
  file. Documented in this story; reviewer confirms it's on.
- **AC-5**: `.github/workflows/ci.yml` also gains an optional
  `npm run test:integration` job, conditional on the secret
  `SUPABASE_SERVICE_ROLE_TEST_KEY` being present — so forks without
  that secret don't break, but the repo owner gets RLS enforcement
  coverage on every PR.

## Risks

| Risk | Mitigation |
|---|---|
| CodeQL flags many false positives on first run → noise | Triage week 1 with `// codeql[…]` suppressions where appropriate; raise issues on real findings. |
| Dependabot floods PRs | Group minor/patch updates per ecosystem; cap to 5 open PRs in the config. |
| `npm audit` blocks legitimate work on a CVE with no fix | `--audit-level=high` lets `moderate` warn without blocking. For high/critical with no fix, document the exception in this story. |
