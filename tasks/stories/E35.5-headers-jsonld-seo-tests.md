# E35.5 — Security-headers + JSON-LD + SEO contract suite

**Epic:** [E35 — Security & GDPR compliance audit + test coverage expansion](../PLAN-2026-05-20-E35-security-compliance-audit.md)
**Effort:** `M` (≤ 2 days)
**Priority:** `P1` (must)
**Status:** 🟡 Ready

## Context

`public/_headers` is the single line of defence for CSP, HSTS,
frame-ancestors, X-Content-Type-Options, Referrer-Policy, and
Permissions-Policy. There is currently zero automated test that the
file stays correct across refactors — a one-character typo or an
accidental `'unsafe-eval'` addition would ship without anyone
noticing. JSON-LD on legal pages is hand-rolled and equally untested.
SEO meta (title, description, canonical, robots) on the four legal
pages is the SEO-quality surface the user explicitly named in scope.

## User story

> As the operator, **I want** the security headers, JSON-LD blobs,
> and SEO meta on every public route to be locked behind contract
> tests, **so that** a careless `_headers` edit or a
> structured-data typo can't ship without CI catching it.

## Acceptance criteria

- **AC-1**: New `tests/security/headers-contract.test.ts` reads
  `public/_headers` as text and asserts:
  - `Strict-Transport-Security: max-age >= 31536000; includeSubDomains; preload`
  - `X-Frame-Options: DENY`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy` denies camera, microphone, geolocation,
    interest-cohort
  - CSP allowlists are a **subset** of an expected set (no domain
    added silently). The expected set lives in a `headers-contract.ts`
    constants file in the test directory.
- **AC-2**: New `tests/security/json-ld-validity.test.ts` renders
  each public route's `head()`, parses every
  `<script type="application/ld+json">` payload, and validates
  against a hand-written Schema.org subset checker. Required types:
  `PrivacyPolicy`, `AboutPage`, `BreadcrumbList`, `WebSite`,
  `WebPageCookiePolicy`. Required fields per type are listed in
  `tests/security/schema-org-shapes.ts`.
- **AC-3**: New `tests/security/seo-meta.test.ts` renders each
  public route via the router test harness and asserts:
  - `<title>` present, unique across routes, ≤ 60 chars.
  - Meta description present, 50–160 chars.
  - Canonical present and matches the route path.
  - OG image present where required (privacy, about, cookies).
  - `robots` meta matches the documented policy
    (legal pages: `index, follow`; quiz/share/admin: `noindex`).
- **AC-4**: New `e2e/specs/security/headers-live.spec.ts` navigates
  to one route from each surface against the live dev server and
  asserts the response headers from the Cloudflare-emulator response
  match the `public/_headers` contract — catches drift between
  `_headers` syntax and actual served headers.
