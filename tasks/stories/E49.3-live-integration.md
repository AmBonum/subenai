## Implementation notes

- **Per-project `globalSetup` is NOT supported by Playwright 1.59**; we use the recommended setup-project pattern (`dependencies` + a tiny `_setup.spec.ts` / `_teardown.spec.ts` that delegate to the shared `globalSetup` / `globalTeardown` functions). This keeps the lifecycle code importable / testable on its own.
- **Rate-limit cap defaults are 50/100; tests drop them to 3/3 via the env bindings passed to wrangler.** If the CF function doesn't actually honor those env vars yet (it reads `env.E49_EXPORTS_PER_*` per `functions/api/tests/export-sessions.ts`), the orchestrator must verify by running the suite — the function does parse them via `parsePositiveInt(env.E49_EXPORTS_PER_*, default)`, so the bindings should take effect.
- **psql password** is supplied via `PGPASSWORD=postgres` in the child env — the default Supabase CLI local creds. No `.pgpass` needed.
- **NULL byte CSV TC** does NOT assert prefix behavior because PostgreSQL rejects NULL bytes in `text` columns; we only assert the export doesn't crash.
- **Auth flow** for API-only specs: password grant against `http://127.0.0.1:54321/auth/v1/token?grant_type=password`, real JWT in `Authorization: Bearer`. The CF function calls `userClient.auth.getUser()` which validates the JWT against Supabase — works against the local stack out of the box.
