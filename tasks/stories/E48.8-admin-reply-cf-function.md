## Context

The CF function that mirrors an admin reply to the user via Resend AND
persists it as a `support_ticket_messages` row so the in-DB thread stays
the source of truth.

## Acceptance criteria

- **AC-1:** Endpoint `/functions/api/support-ticket-reply.ts` (POST). Body: `{ ticket_id, body, attachment_ids?: string[] }`.
- **AC-2:** Auth validation:
  - Bearer token in `Authorization` header
  - Calls Supabase `auth.getUser(token)` to resolve user id
  - Calls `public.has_role(user_id, 'admin')`
  - Validates JWT claim `aal = 'aal2'`
  - If any check fails: 401 + audit-log a `support_reply_auth_failed` event
- **AC-3:** Validation:
  - `body` 1–10000 chars
  - `ticket_id` resolves to an existing non-deleted ticket
  - all `attachment_ids` (if provided) belong to this admin's previous uploads AND have `scan_status='clean'`
- **AC-4:** Transactional:
  - `INSERT INTO support_ticket_messages (...)` with `author_kind='admin'`, `author_user_id=admin.id`, `author_name=admin.display_name`
  - Re-parent any pending admin attachments by setting `message_id` on the inserted row
  - `UPDATE support_tickets SET status = 'waiting_user', updated_at = now(), assigned_to = COALESCE(assigned_to, admin.id) WHERE id = ticket_id`
  - `audit_log` row: `action='support_admin_reply_sent'`
- **AC-5:** Outbound email:
  - To: `ticket.submitter_email`
  - Reply-To: `ticket+{ticket_id}@subenai.sk`
  - Subject + body from `supportTicketReplyEmail({...})` (E48.5)
  - Idempotency-Key: `support-ticket-{ticket_id}-reply-{message_id}`
  - `email_message_id` stored on the messages row from the Resend response
- **AC-6:** On Resend failure (5xx / network error): the message row is STILL inserted (so the admin sees their reply in the thread); the status flip happens; a `support_reply_email_failed` event is audit-logged + an admin alert is dispatched ("Reply persisted but email did not send — please retry").
- **AC-7:** Response 200 `{ message_id, email_message_id? }`. Response 4xx with `{ error: <code>, message: <human-readable Slovak> }`.
