# E38.4 — Live-SQL integration tests for retention RPCs

**Epic:** [E38 — Retention crons + auto-anonymisation](../PLAN-2026-05-20-E38-retention-crons.md)
**Effort:** `M` (≤ 2 days)
**Priority:** `P2`
**Status:** 🟡 Ready

## Context

E35.2 set up `tests/integration/security/` against a local Supabase.
This story adds retention coverage to the same harness: seed rows at
specific ages, invoke each retention RPC, assert the right rows
transitioned + the wrong rows untouched.

## Acceptance criteria

- **AC-1**: New file
  `tests/integration/security/retention.test.ts` using the existing
  `setup-supabase.ts` fixture.
- **AC-2**: Three `describe` blocks (one per RPC):
  - `purge_expired_attempts` — seed: 37-mo old row + 35-mo old row.
    Call RPC. Assert 37-mo gone, 35-mo present.
  - `anonymize_expired_anticheat` — seed: 13-mo row with flags + 6-mo
    row with flags. Call RPC. Assert 13-mo `flags = '[]'::jsonb` AND
    `score` unchanged; 6-mo untouched.
  - `anonymize_expired_edu_respondents` — seed: 13-mo edu row + 6-mo
    edu row, both with name + email. Call RPC. Assert 13-mo
    respondent columns NULL; 6-mo untouched.
- **AC-3**: Each test uses `service_role` client to seed AND to call
  the RPC (anon does not have EXECUTE per AC-5 of E38.1/E38.2).
- **AC-4**: A 4th `describe` block: "service-role can call RPCs, anon
  cannot" — assert anon client gets an error when calling each RPC
  directly.
- **AC-5**: Test file follows the existing `tests/integration/`
  conventions — `getLocalSupabase()` from
  `tests/integration/security/setup-supabase.ts`, skip-with-marker if
  Supabase isn't reachable.
