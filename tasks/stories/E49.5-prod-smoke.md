## Goal

Land the 8 PS-* test cases from the plan as a post-merge canary that
exercises the real `/app/tests` respondent drill-down feature on
production, so a CF Pages bundle that breaks the listing / KPI / sheet /
CSV-export pipeline is caught within minutes of the deploy.

## Acceptance criteria

- `supabase/scripts/seed-e49-prodsmoke-data.sql` provisions 1 published
  test owned by TU-A (`e2e00001-e49a-4001-8001-0000aaaaaa01`), 3
  questions, 3 sessions (1 completed named, 1 completed anonymous, 1
  in_progress), 6 session_answers. ID prefix is the literal
  `e2e-e49-prodsmoke-` on text PKs (`slug`, `share_id`) and the shared
  `e2e00001-e49a-4001-8001-*` namespace on UUID PKs. `BEGIN…COMMIT`,
  `ON CONFLICT DO UPDATE / DO NOTHING` — safe to re-run.
- `e2e/specs/prod-smoke/e49-sessions.spec.ts` covers PS-01..PS-08:
  login via UI as TU-A → `/app/tests` → open canary → KPI cards visible
  → sessions list ≥ 1 row → open detail sheet → close → CSV export 200
  with attachment headers → sign-out clean.
- `e2e/poms/prod-smoke/E49ProdSmokePage.ts` is the POM the spec
  consumes — every locator goes through a getter (CLAUDE.md § "POM-only
  locators"). Exports `E49_PRODSMOKE` constants matching the seed.
- `.github/workflows/e49-prod-smoke.yml` triggers on `workflow_dispatch`
  + `push` to `main` filtered to the relevant paths (`src/routes/app.tests.**`,
  `src/components/app/tests/**`, `functions/api/tests/**`,
  `e2e/specs/prod-smoke/**`, the POM dir, and the workflow file itself).
  Job runs `npx playwright test --project=prod-smoke --grep "E49"` with
  an `if: always()` teardown psql step that DELETEs every row matching
  `slug LIKE 'e2e-e49-prodsmoke-%'`.
- Spec passes `npx playwright test --project=prod-smoke --list`
  discovery without runtime execution (running against prod is the
  workflow's job, not the local agent's).
- CHANGELOG entry under "Pridané (interné)".

## Out of scope

- Negative scenarios on prod (IDOR, rate-limit, CSV-injection battery)
  — these live on Layer B (`e2e-live-supabase`) per the plan.
- Mobile / tablet projects — Layer A only.
- Auth bootstrap (TU-A is already provisioned on prod by
  `seed-e49-e2e-users.sql`; the matching SQL was pasted at the
  Phase 1c-1 merge).

## Implementation notes

- `test.skip(!process.env.CI_PROD_SMOKE, ...)` guards the spec so a
  stray local `npx playwright test` never fires against prod.
  `playwright.config.ts` already excludes the prod-smoke project from
  the e2e-chromium / mobile / tablet projects.
- Teardown is mandatory — no `if: success()` carve-out. A flaky run
  must not leak rows; the next workflow trigger will re-seed if needed.
- Cleanup is prefix-scoped (`LIKE 'e2e-e49-prodsmoke-%'`) so the
  permanent `e2e-e49-` live-integration data set on prod (Phase 1c-1)
  is untouched.
- The CSV-export assertion uses `page.waitForResponse` on the
  `/api/tests/export-sessions` endpoint rather than chasing the
  download blob — the response headers are the contract, the file body
  has its own SEC-08..SEC-18 battery on Layer B.
