## Context

Keď autor zapne *Náhodné poradie*, každý respondent musí dostať vlastné
poradie otázok — ale **rovnaký** respondent pri obnovení stránky musí
vidieť to isté poradie, inak by sa rozsypal in-progress session resume.

Determinizmus dosahujeme seedovaním PRNG hashom `session.id`. Server
zostáva stateless o UI poradí — `session_answers` perzistujú podľa
`question_id`, nie pozície.

## Akceptačné kritériá

- **AC-1:** `src/lib/quiz/shuffle.ts` exportuje 4 pure funkcie:
  - `fnv1a32(string): number` — 32-bit unsigned hash.
  - `mulberry32(seed: number): () => number` — PRNG factory, hodnoty v [0,1).
  - `shuffleBySessionId<T>(items, sessionId): T[]` — Fisher-Yates,
    nemutuje vstup, vracia novú kópiu; pre length ≤ 1 vracia kópiu beze
    zmeny.
  - `resolveQuestionOrder(ids, mode, sessionId | null): string[]` —
    keď `mode === 'fixed'` alebo `sessionId === null`, vracia ids.slice();
    inak deleguje na `shuffleBySessionId`.
- **AC-2:** `SafeTestProjection` v `src/lib/respondent/take-test.functions.ts`
  obsahuje pole `question_order_mode: "fixed" | "random"`. `SAFE_TEST_COLUMNS`
  bol rozšírený o `question_order_mode` (NIE o password_hash, owner_id,
  source_template_id).
- **AC-3:** `TakeTestFlow` aplikuje `resolveQuestionOrder` cez `useMemo`
  závisle od `(questionIds, test.question_order_mode, sessionId)`.
  Pred `sessionId` zostáva DB poradie (pre-intake render nikdy neukáže
  pomiešané otázky).
- **AC-4:** Tests `tests/lib/quiz/shuffle.test.ts` (18 testov) pokrývajú:
  determinizmus per session, divergenciu medzi rôznymi session_id,
  invariancia veľkosti množiny, nemutáciu vstupu, edge cases [0, 1],
  fixed mode return-as-is, null sessionId return-as-is.
