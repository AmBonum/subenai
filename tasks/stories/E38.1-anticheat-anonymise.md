# E38.1 — Anti-cheat anonymisation function

**Epic:** [E38 — Retention crons + auto-anonymisation](../PLAN-2026-05-20-E38-retention-crons.md)
**Effort:** `S` (≤ ½ day)
**Priority:** `P1`
**Status:** 🟡 Ready

## Context

`/privacy` s3 row `anticheat` declares 12-month retention with legal
basis Art. 6(1)(f). The anti-cheat data lives inline in `attempts.flags`
(JSONB) and `attempts.total_time_ms`. Today there is no function to
anonymise these columns after 12 months — they ride along with the
36-month `purge_expired_attempts()` cron, which means the actual
retention is 36 months, not 12.

We add `public.anonymize_expired_anticheat()` mirroring the existing
`purge_expired_attempts()` pattern from
`supabase/migrations/20260426110000_self_service_delete_and_retention.sql`.

## Acceptance criteria

- **AC-1**: New migration `supabase/migrations/{ts}_anticheat_anonymise.sql`
  creates `public.anonymize_expired_anticheat()` as a
  `SECURITY DEFINER` function with pinned `search_path = public, pg_temp`.
- **AC-2**: Function updates `attempts` rows where
  `created_at < now() - interval '12 months'` AND
  (`flags IS NOT NULL AND flags <> '[]'::jsonb` OR `total_time_ms IS NOT NULL`):
  - Sets `flags = '[]'::jsonb`
  - Sets `total_time_ms = NULL`
  - Returns the number of rows touched as an INT.
- **AC-3**: Function does NOT touch `score`, `final_score`, `breakdown`,
  `personality`, `nickname` — only the anti-cheat-specific columns.
- **AC-4**: `forbid_attempt_score_changes` trigger is bypassed because
  we don't modify score columns. (Verify in the integration test.)
- **AC-5**: `GRANT EXECUTE ... TO service_role` so the GH Actions cron
  worker can call it. `REVOKE EXECUTE ... FROM PUBLIC`.
- **AC-6**: `DEPLOY_SETUP.sql` includes the new migration (E38.5
  coordinates this).
